1. THE REAL BUSINESS OBJECTIVE
======================================================================

The objective is not to demonstrate OCR, build an impressive architecture diagram or create another generic document-processing library.

The objective is:

“Prove that Genuity can convert large collections of messy, incomplete industrial documents into trustworthy, evidence-linked, system-ready data at a dramatically lower total cost than manual processing or sending every page to an expensive VLM.”

A service company such as LTTS already possesses:

- OCR technology
- Document-extraction pipelines
- VLM access
- Data engineers
- Quality-checking processes
- Client-specific templates
- Possibly patented OCR components

Therefore, do not compete with their OCR.

Genuity must plug into their existing extraction stack and solve what remains:

- Uncertain fields
- Missing values
- Broken tables
- Inconsistent formats
- Cross-document relationships
- Conflicting records
- Validation
- Evidence
- Expensive exception handling
- Repeated manual data preparation

The compelling proposition is:

“Keep your OCR and existing VLMs. Genuity transforms their incomplete output into validated, connected records and resolves supported exceptions using deterministic logic, cross-document evidence and inexpensive local processing.”

======================================================================
4. HARD ENGINEERING PRINCIPLES
======================================================================

The cheapest reliable method must always run first.

Required processing order:

1. Cached result
2. Exact template or deterministic parser
3. Existing OCR output
4. Rules and normalisation
5. Cross-document retrieval
6. Domain constraints
7. Small local model, if available
8. Cropped-region VLM call, if explicitly permitted
9. Human review
10. UNRESOLVED

Never send the complete document to a VLM when one uncertain region is sufficient.

Never call a model again when an identical content hash has already been processed.

Never use a generative model for a value that can be calculated or retrieved deterministically.

Never automatically accept a field merely because a model is confident.
